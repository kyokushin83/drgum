닥터검역 Travel Pass 설치 및 테스트 안내
========================================

구성 파일
---------
- index.html: 기존 공개 견적 홈페이지(원본 유지)
- travel.html: 고객 전용 진행 현황 화면
- admin.html: 고객 등록/수정/삭제 관리자 화면
- app.css: Travel Pass 공통 디자인
- data-store.js: localStorage 데이터 계층
- travel.js: 고객 화면 로직
- admin.js: 관리자 화면 로직
- CNAME: 기존 사용자 도메인 pet-travel.co.kr 유지

GitHub Pages 업로드
-------------------
1. 이 폴더 안의 파일을 GitHub Pages 저장소의 최상위 경로에 업로드합니다.
2. 기존 홈페이지 사진 파일도 같은 최상위 경로에 둡니다.
   - doctor-quarantine-store.png
   - doctor-quarantine-interior-1.png
   - doctor-quarantine-interior-2.png
3. GitHub 저장소의 Settings > Pages에서 배포 브랜치와 /(root)를 선택합니다.
4. 배포 후 공개 홈페이지는 /index.html, 관리자는 /admin.html에서 엽니다.

빠른 테스트
-----------
1. admin.html을 엽니다.
2. 기본 샘플 고객 "김하늘 / 몽이 / 일본"이 보이는지 확인합니다.
3. 고객 URL 복사를 누르거나 미리보기를 엽니다.
4. travel.html?id=A7K29X 화면에서 D-day, 진행률, 현재 단계, 다음 방문일,
   체크리스트와 메모가 표시되는지 확인합니다.
5. 관리자에서 단계 체크 또는 메모를 변경하고 저장한 뒤 고객 화면을 새로고침합니다.
6. 고객 추가와 삭제도 각각 한 번씩 확인합니다.

중요한 1차 버전 제한
--------------------
- 데이터는 서버가 아니라 현재 브라우저의 localStorage에만 저장됩니다.
- 같은 주소라도 다른 브라우저나 고객의 휴대폰에서는 관리자 브라우저의 데이터가 보이지 않습니다.
- 브라우저 데이터 삭제 시 고객 정보도 삭제됩니다.
- 따라서 이 버전은 화면/업무 흐름 테스트용입니다. 실제 고객 공유 운영 전에는 인증과 접근
  제어가 적용된 Firebase 또는 별도 서버 데이터베이스로 교체해야 합니다.
- 공개 Google Sheet에는 보호자명, 연락처, 일정, 메모 등 개인정보를 절대 저장하지 마세요.

데이터 계층 교체
----------------
data-store.js의 TravelPassStore가 화면과 저장소 사이의 어댑터입니다.
Firebase 연동 시 list, get, save, remove 메서드를 동일하게 제공하는 비동기 어댑터로 교체하고,
admin.js와 travel.js의 호출부를 async/await 방식으로 바꾸면 됩니다.

로컬 테스트 참고
----------------
파일을 직접 더블클릭해도 기본 기능은 동작합니다. 다만 브라우저 보안 정책에 따라 클립보드 복사가
제한될 수 있으므로 GitHub Pages 주소에서 테스트하는 것을 권장합니다.
