닥터검역 Travel Pass / Firestore 운영 안내
=========================================
현재 구현: 기존 dr-quarantine-consultations Firebase 프로젝트를 재사용합니다.
firebase-config.js는 공개 웹 설정만 포함합니다. 서비스 계정 비밀키는 절대 저장소에 넣지 않습니다.
고객 데이터 저장·조회는 travelPassEnabled=true로 활성화되었습니다.
2026-10-12 사용자가 규칙 게시 완료를 알렸고 익명 고객 문서 접근의 PERMISSION_DENIED(403)를 확인했습니다.
관리자 및 고객 계정으로 실제 저장·조회·권한 테스트는 아직 필요합니다. 아래는 설정과 검증 절차입니다.

1. Firebase Console > dr-quarantine-consultations > Authentication
   - Google 로그인 활성화 상태 확인.
   - Authorized domains에 pet-travel.co.kr 및 실제 사용하는 Pages 도메인을 등록.
   - 관리자는 기존 허용된 세 Google 계정으로 로그인합니다.
   - firebase-config.js의 adminEmails와 firestore.rules의 관리자 목록은 동일하게 관리.
2. Firestore > Rules
   - 기존 규칙을 백업하고 이 저장소의 firestore.rules와 비교.
   - 저장소에는 기존 규칙 원본이 없으므로 다른 서비스가 있는지 먼저 확인.
   - 이 규칙은 travelCustomers와 기존 consultations만 허용하며 나머지는 차단.
   - 콘솔에서 게시하거나 Firebase CLI로 배포:
     firebase deploy --only firestore:rules --project dr-quarantine-consultations
   - firebase.json/.firebaserc도 준비되어 있습니다. GitHub Pages 배포는 Firestore 규칙을 배포하지 않습니다.
3. 활성화 전에 Rules Playground 또는 Emulator로 아래 접근을 반드시 검증
   - 비로그인: travelCustomers 단건/목록/추가/수정/삭제 모두 거부.
   - 관리자: 생성/목록/조회/수정/삭제 허용. createdAt/createdBy 변경 거부.
   - 고객 A: customerUid가 A의 UID인 문서의 get만 허용.
   - 고객 A의 목록 조회, 고객 B 문서 조회, 모든 쓰기 거부.
   - Firebase 프로젝트/DB가 운영용인지 확인. 테스트 모드나 전체 공개 규칙 사용 금지.
   - 기존 견적 상담요청 생성과 관리자 조회/통화완료 변경이 계속 동작하는지 확인.
4. 검증 후 firebase-config.js의 travelPassEnabled를 true로 바꾸고 main에 커밋/푸시.
   관리자에서 테스트 고객 추가 -> 새로고침 -> 다른 기기 관리자 로그인 후 조회 -> 수정 -> 삭제 확인.
5. 기존 고객 이관
   - 예전에 고객을 입력했던 동일 기기/브라우저/도메인에서 admin.html을 열고 로그인.
   - "이 브라우저의 기존 고객 가져오기"를 클릭.
   - localStorage의 drQuarantine.travelPass.customers.v1만 읽어서 이관합니다.
   - 원본은 지우지 않으며 Firestore에 이미 있는 ID는 덮어쓰지 않습니다.
   - 기본 데모 김하늘/몽이/A7K29X는 제외합니다. 다른 데모 기록은 사용자가 확인하세요.
   - 오류로 일부만 이관됐으면 다시 클릭: 이미 등록된 ID를 건너뛰므로 재시도 가능.
   - 다른 기기/브라우저의 localStorage는 각각 별도로 이관해야 합니다.
6. 고객 URL
   - 고객이 travel.html에서 Google 로그인하면 본인 Firebase Auth UID가 표시됩니다.
   - 담당자는 고객의 Google 계정을 확인하고 Authentication > Users에서 UID를 대조.
   - 고객 등록/수정 화면의 "고객 Firebase Auth UID"에 등록 후 저장.
   - 저장된 고객에 UID가 지정되어야 URL 복사/미리보기가 활성화됩니다.
   - URL 형식: https://pet-travel.co.kr/travel.html?id=<Firestore 문서 ID>
   - URL은 식별자이며 접근 암호가 아닙니다. 다른 기기에서도 지정된 계정으로 로그인해야 열립니다.
   - 새 고객 ID는 crypto.randomUUID(). 기존 이관 고객은 기존 ID 유지.
   - UID 제거/변경으로 기존 계정의 이후 조회 권한을 해제할 수 있습니다.
   - 고객은 자기 문서만 조회합니다. 메모와 일정 등 문서의 모든 필드는 고객에게 보일 수 있습니다.
     내부 직원 전용 기록을 memo에 넣지 마세요. 별도 관리자 전용 컬렉션이 필요합니다.

컬렉션 및 문서
--------------
travelCustomers/{customerId}
  guardianName, petName, country: 필수 문자열
  departureDate: YYYY-MM-DD (필수), nextVisitDate: YYYY-MM-DD 또는 빈 문자열
  currentStepId, completedStepIds: 진행 단계 ID 및 완료 ID 배열
  steps: [{id, name, description, days}] / 저장 당시 국가별 일정 스냅샷
  nextAction, memo: 고객에게 표시할 안내 내용
  customerUid: Firebase Auth UID (빈 문자열이면 관리자만 조회)
  schemaVersion: 1
  createdAt/updatedAt: Firestore 서버 timestamp
  createdBy/updatedBy: 작업한 관리자 Firebase UID
consultations/{autoId}: 기존 홈페이지 상담요청, 기존 필드 유지

운영 방식
---------
관리자 UI와 공개 일정표 Google Sheet는 유지합니다. Sheet에는 고객 개인정보를 쓰지 않습니다.
저장 API: firebase-store.js의 비동기 list/get/save/remove; save는 트랜잭션이며 서버 승인 후 성공 표시.
로그인은 세션 단위로 유지하고 고객 문서는 Firestore 메모리 캐시만 사용합니다.
브라우저 localStorage에 새 고객 정보를 저장하는 대체 경로는 없습니다.
실제 서버 저장 후에는 새로고침 및 다른 기기에서도 권한 있는 계정으로 같은 문서를 조회합니다.
GitHub에는 코드/규칙/설명만 저장되며 고객 정보는 커밋되지 않습니다.
공개 상담요청은 기존대로 생성만 허용하므로 스팸 방지는 별도 App Check/서버 제한을 검토할 수 있습니다.

기존 코드 분석 (변경 전)
----------------------
admin.html -> admin.js -> data-store.js
TravelPassStore.save() -> localStorage.setItem(STORAGE_KEY, JSON.stringify(customers)).
STORAGE_KEY = drQuarantine.travelPass.customers.v1.
고객 추가 버튼은 메모리에 빈 폼만 만들며 "저장하기"를 눌러야 localStorage에 기록됐습니다.
같은 브라우저/도메인의 새로고침 및 재실행 후 유지, 데이터 삭제/시크릿 세션 종료 시 유실 가능.
다른 기기/브라우저/도메인에 동기화되지 않으며 기존 고객 URL도 해당 로컬 데이터가 있어야 조회.
sessionStorage, 고객 저장 API, Google Sheet 고객 쓰기, GitHub 저장소 쓰기는 없었습니다.
단, 별도 consultation-client.js/consultation-admin.js는 이미 Firebase consultations를 사용했습니다.

검증 범위
---------
배포 전 JavaScript 구문 검사와 모의 Firestore 저장/조회/수정/삭제·권한 차단·이관 재시도 검증.
실제 Firebase Auth 로그인, 서버 보안 규칙/CRUD, Emulator 검증은 콘솔 접근 불가로 미실행.
활성화 전 위 접근 테스트를 실행하세요.
